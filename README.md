# JapanChecker

大量のドメイン一覧から、日本国内の営業対象になり得る事業者サイトを抽出し、
`result.csv` として営業リスト化するツールです。

## フォルダ構成

```
JapanChecker/
├ app.js               … サーバー本体・スクレイピング・スコアリング・CSV出力・パスワード認証
├ score_config.js       … 配点設定(ここだけ変更すれば点数を調整できる)
├ package.json          … 依存ライブラリの定義
├ domains.txt           … 解析したいドメイン一覧(1行1ドメイン)
├ result.csv            … 実行結果が出力されるCSV(全結果、スコア0は除く)
├ history.json          … 見つかった事業者の台帳(詳細情報つき・自動蓄積・削除しない限り消えない)
├ call_status.json      … 架電済みかどうかの記録(テレアポ用、ドメイン単位)
├ .progress.log         … レジューム(続きから再開)用の内部ログ
└ public/
   └ index.html         … ブラウザ画面(開始・停止・進捗・タブ・通知)
```

## インストールコマンド

Node.js (18以上推奨) がインストールされている環境で、
`JapanChecker` フォルダに移動して以下を実行してください。

```bash
cd JapanChecker
npm install
```

これで `express` `axios` `cheerio` が自動的にインストールされます。

## パスワードを設定する(社内共有する前に必ず設定)

このアプリには**Basic認証**(ブラウザ標準のID・パスワード入力画面)がかかっています。
何も設定しないと、ID: `admin` / パスワード: `changeme` という初期値のまま動いてしまうので、
社内の人に共有する前に必ず自分たちのID・パスワードに変更してください。

**Windows(PowerShell)の場合**

```powershell
$env:APP_USERNAME="admin"
$env:APP_PASSWORD="ここに好きなパスワードを入れる"
npm start
```

**Mac / Linuxの場合**

```bash
APP_USERNAME=admin APP_PASSWORD=ここに好きなパスワードを入れる npm start
```

起動時に、パスワードが初期値のままだとターミナルに警告が表示されます。

このID・パスワードは、この後アクセスする**全員が同じものを使います**
(1人1アカウントではなく、共有の合言葉のようなものです)。

## 起動方法

```bash
npm start
```

起動すると以下のように表示されます。

```
JapanChecker running: http://localhost:3000
```

自分のパソコンでブラウザを開き、`http://localhost:3000` にアクセスすると、
ID・パスワードの入力画面が出ます。上で設定したものを入力してください。

## 社内の他の人からもアクセスできるようにする

自分のパソコンでサーバーを起動したまま、同じ社内ネットワーク(Wi-Fi/LAN)内の
他のパソコンからもアクセスできます。

1. サーバーを起動している自分のパソコンのIPアドレスを確認します。
   - Windows: PowerShellで `ipconfig` を実行し、「IPv4 アドレス」を確認(例: `192.168.1.23`)
   - Mac: 「システム設定 → Wi-Fi → 詳細」などで確認
2. 他のパソコンのブラウザで、次のようにアクセスしてもらいます。

   ```
   http://(確認したIPアドレス):3000
   ```

   例: `http://192.168.1.23:3000`

3. 上で設定したID・パスワードを入力すれば、同じ画面が使えます。

**注意点**
- 自分のパソコンで `npm start` を実行している間だけアクセス可能です。パソコンをスリープ・
  シャットダウンすると他の人もアクセスできなくなります。
- 会社のネットワーク設定によっては、Windowsのファイアウォールでブロックされることがあります。
  アクセスできない場合は、Windowsのファイアウォール設定で3000番ポートの受信を許可してください。
- これは**社内ネットワークの中だけ**でアクセスできる状態です。外出先やスマホの回線からは
  アクセスできません。外からもアクセスできるようにしたい場合は、社内サーバーやcrラウド
  (AWS/GCPなど)へのデプロイが必要になるので、その際は改めてご相談ください。
- HTTP(暗号化なし)で通信しているため、社外のインターネットに晒す構成にはこのままでは
  向きません。あくまで「信頼できる社内ネットワークの中だけで使う」用途を想定しています。

## 使い方

1. ブラウザ画面を開くと、一番上に「解析したいドメイン一覧」という入力欄があります。
   ここに調べたいドメインを1行ずつ入力(または貼り付け)し、「この内容を保存する」ボタンを押します。

   ```
   example.com
   example.jp
   sample.net
   ```

   `https://example.com/` や `www.example.jp` のように、URLをそのまま貼り付けても
   自動的にプロトコルやパスを取り除いてドメイン名だけを認識します。
   （同じドメインが重複していた場合も自動でまとめられます)

   手元にドメイン一覧の入ったテキストファイル(.txt)がある場合は、「…またはテキストファイルを
   選んで読み込む」からファイルを選ぶと、その内容が入力欄に読み込まれます(読み込んだだけでは
   保存されないので、必ず「この内容を保存する」を押してください)。

   ※ パソコン上で直接 `npm start` している場合は、`domains.txt` をメモ帳等で直接編集しても
   同じように反映されます。Render等にデプロイしている場合は、サーバー上のファイルに直接触れないため、
   この画面からの入力・保存が必要になります。

2. ブラウザ画面(`http://localhost:3000`)を開き、「解析を開始」ボタンを押します。
3. 画面に進捗(処理件数 / 全体件数)が表示されます。
   - 内部的には `domains.txt` を1件ずつアクセスし、
     電話番号・日本語・住所・お問い合わせページなどをチェックしてスコアリングします。
   - 結果は処理が終わるたびに `result.csv` へ随時書き込まれるため、
     途中でサーバーを止めてしまっても、それまでの結果は失われません。
4. 解析が終わったら「result.csv をダウンロード」ボタンを押すとCSVを取得できます。
   (サーバーの `JapanChecker/result.csv` を直接開いても構いません)

### コマンドラインだけで使いたい場合

ブラウザを使わず、サーバー起動後に以下のようにAPIを直接呼んでも実行できます。

```bash
curl -X POST http://localhost:3000/api/start
curl http://localhost:3000/api/status
curl -o result.csv http://localhost:3000/api/download
```

## スコアリングの仕組み

`score_config.js` に書かれた点数だけを見て `app.js` が合算します。
配点を変更したい場合は `app.js` を触らず、このファイルの数値だけ書き換えてください。
(左側の英語名はプログラム内部の項目名、右側がCSVに出る日本語の見出しです)

```js
module.exports = {
  jp_domain: 10,          // → CSVの「JPドメイン」列
  japanese_text: 10,      // → CSVの「日本語検出」列
  lang_ja: 10,             // → CSVの「lang=ja指定」列
  business_name: 20,      // → CSVの「事業者名検出」列
  japanese_address: 20,   // → CSVの「日本住所検出」列
  contact_page: 10,        // → CSVの「お問い合わせページ」列
  company_page: 5,         // → CSVの「会社概要ページ」列
  google_map: 5,           // → CSVの「Googleマップ」列
  access_page: 5,           // → CSVの「アクセスページ」列
  business_page: 5,         // → CSVの「事業内容ページ」列
};
```

CSVの各列は「〇」(該当あり)・「×」(該当なし)、判定列は「対象」(スコア対象)・
「対象外」(除外)で表示されます。

## 除外条件

以下に該当するサイトは `status = NG` として除外され、`reason` 列に理由が記録されます
(CSVからは削除されず、除外理由付きで残ります)。

- 日本電話番号が検出できない(必須条件)
- 海外TLD(`.kr` `.cn` `.tw` `.hk`)
- ハングルが大量に検出される
- 中国語(漢字のみでひらがな・カタカナが無い)が大量に検出される
- アクセス不可・タイムアウト

## 架電済みチェック(テレアポ用)

「全結果」「未架電リスト」どちらのタブにも一覧表(「一覧を更新」ボタンで表示)が出ます。
各行の左端にある「架電」列のチェックボックスにチェックを入れると、その場でドメインごとの
架電済みステータスが `call_status.json` に保存されます。

- チェックを入れた行はグレーアウト・取り消し線で表示され、一目で分かるようになっています。
- 「未架電のみ表示」にチェックを入れると、架電済みの行を一覧から一時的に隠せます。
- ステータスは `call_status.json` にドメイン単位で保存され、ブラウザを閉じても消えません。
- 一覧表の表示件数は最大 `MAX_TABLE_ROWS`(デフォルト1000件)までです。
  それを超える件数がある場合は先頭からその件数だけ表示され、画面上部に
  「表示は先頭◯件までです」と表示されます。全件を確認したい場合はCSVをダウンロードしてください
  (CSV自体には架電済み列は含まれていません。架電状況はブラウザ画面上でのみ確認できます)。

## 新着(新規発見)と未架電リストについて

過去に見つかった事業者は `history.json` という台帳ファイルに、詳細情報つきで自動的に
記録され続けます(このファイルは手動で削除しない限り消えません)。

- **「未架電リスト」タブ**には、**見つかった時期に関わらず**、まだ架電していない
  (=架電済みチェックが入っていない)事業者が全て表示されます。
  今日見つかったものも、1ヶ月前に見つかってまだ架電できていないものも、
  区別なく一覧に並びます。架電済みにチェックを入れると、この一覧から自動的に消えます。
- 一覧は「見つかった日時が新しい順」に並びます。
- 実行が完了したタイミングで**今回新しく見つかった**事業者が1件以上あれば、
  ブラウザ通知でお知らせします(画面の「ブラウザ通知を許可する」ボタンを
  先に押して許可しておく必要があります)。この「新規発見件数」は、画面上部の
  状態表示にも表示されます。

### 運用イメージ

1. 初回実行: 見つかった事業者はすべて `history.json` に記録され、未架電リストに並びます。
2. 架電したら、その行の「架電」チェックを入れます。以後その事業者は未架電リストから消えます。
3. 後日、`domains.txt` を最新のドメイン一覧に更新して再度「解析を開始」を押す
   (このとき「続きから再開する」のチェックは外してください。外すと `result.csv` は
   最初から作り直されますが、`history.json` は消えないので、これまでの未架電リストは
   そのまま引き継がれます)。
4. 新しく見つかった事業者は未架電リストに追加され、まだ架電していない古い事業者と
   合わせて一覧表示されます。

### 台帳をリセットしたい場合

`history.json` を削除(または中身を `{}` に)してから実行すると、
それまでの記録はすべて消え、次回の実行結果だけが台帳に残ります。

## 出力について

- **スコアが0点のドメインは `result.csv` に出力されません。**電話番号未検出などで除外されたドメインも同様です。
- 進捗管理(「続きから再開する」機能)は `result.csv` とは別に `.progress.log` という内部ファイルで行っています。
  スコア0で書き込まれなかったドメインも、再開時に再チェックされることはありません。
  (`.progress.log` は削除しても動作に支障はありませんが、削除すると次回「続きから再開する」を使ったときに
  最初からやり直しになります)

## 5000件〜7万件規模での運用

### 途中で止める・続きから再開する

- 画面の「停止」ボタンを押すと、それ以降の未処理ドメインへのアクセスを打ち切ります
  (既に走っているリクエストが終わり次第、新規のリクエストは行いません)。
  それまでの結果は `result.csv` に残っています。
- 続きから再開したいときは、「続きから再開する」にチェックを入れてから
  「解析を開始」を押してください。`result.csv` に既に記録済みのドメインはスキップされ、
  未処理分だけを追記で処理します。
- チェックを入れずに「解析を開始」した場合は `result.csv` が初期化され、最初からやり直します。

### サーバーのプロセスごと落ちてしまった場合

`result.csv` に処理済みの結果は残っているので、サーバーを `npm start` で立て直し、
画面で「続きから再開する」にチェックを入れて再度「解析を開始」を押せば、
未処理分だけ続きから処理できます。

### パフォーマンス調整(環境変数)

Renderの場合は「Environment」タブで設定します。自分のPCで動かす場合は、起動時に
環境変数として指定します。

```bash
# 例: 同時処理数を上げ、タイムアウトを短くする
DOMAIN_CONCURRENCY=20 PAGE_CONCURRENCY=3 REQUEST_TIMEOUT=6000 npm start
```

| 環境変数 | デフォルト | 説明 |
|---|---|---|
| `DOMAIN_CONCURRENCY` | 15 | 同時に処理するドメイン数 |
| `PAGE_CONCURRENCY` | 3 | 1ドメイン内で同時に取得する内部ページ数 |
| `MAX_SOCKETS` | 200 | 同時に張れるHTTP接続数の上限(DOMAIN_CONCURRENCY×PAGE_CONCURRENCYより十分大きくしておく) |
| `REQUEST_TIMEOUT` | 8000 (ms) | 1リクエストのタイムアウト |
| `RETRY_COUNT` | 1 | タイムアウト等の一時的なエラー時の再試行回数 |
| `RETRY_DELAY` | 1000 (ms) | 再試行までの待機時間 |
| `PORT` | 3000 | サーバーのポート |

**注意**: `DOMAIN_CONCURRENCY` を極端に上げると、相手サーバーへの負荷が高くなったり、
自分の回線・PCのリソースを圧迫したりします。`15〜30` 程度を目安に、
様子を見ながら調整することをおすすめします。

### そのほかの高速化・耐障害性の工夫

- HTTP接続を使い回す(`keep-alive`)ことで、大量アクセス時の速度を改善しています。
- 一時的な接続エラー(タイムアウト・接続リセットなど)は自動的に1回だけ再試行します
  (`RETRY_COUNT`で回数変更可)。
- 結果は処理が終わるたびに逐次CSVへ書き込むため、7万件規模でもメモリを圧迫しません。
- 見つかった事業者は`history.json`に**見つかった瞬間**に1行ずつ追記されるため、
  実行が全部終わるのを待たなくても、「未架電リスト」タブにリアルタイムで反映されます
  (実行中は約10秒おきに自動更新されます)。
- 同じドメインを何度も再チェックしていると `history.json` の行数が増えていきます。
  「未架電リスト」タブの「履歴を整理する」ボタンを押すと、ドメインごとに最新の1行だけを
  残して整理できます。

### 7万件規模を1回で処理する場合の目安・注意点

- **所要時間**: サイトの応答速度や混雑状況によりますが、数万件規模になると
  **数時間〜半日程度**かかることが多いです。少しずつ試して、実際の処理速度を見ながら
  時間を見積もることをおすすめします。
- **Renderの無料プランを使っている場合の注意**: 無料プランは、一定時間アクセスが無いと
  自動的にスリープし、実行中の処理も止まってしまいます。ブラウザの画面を開いたままにしておくと、
  進捗確認の通信が定期的に発生するため、スリープを防げます。**実行中はブラウザのタブを
  閉じたり、パソコンをスリープさせたりしないでください。**
  それでも途中で止まってしまった場合は、「続きから再開する」で再開すれば、
  それまでの結果を無駄にせず続きから処理できます。
- 大量件数を一度に処理するのが不安な場合は、`domains.txt` を1万件ずつなど分割し、
  「続きから再開する」を使わずに区切って実行する運用も可能です。

## 注意事項

- 本ツールは対象サイトへ自動アクセスします。相手サーバーに過度な負荷をかけないよう、
  同時処理数やアクセス間隔にはご配慮ください。
- 取得先サイトの利用規約・robots.txt等を確認の上、ご利用ください。
